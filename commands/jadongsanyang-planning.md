# 자동사냥 Planning

코드베이스를 분석하여 리팩토링, 신규 기능, UX 개선 아이디어를 발굴하고 `/todos/`에 저장합니다.

## 인자

`$ARGUMENTS`로 분석 대상을 지정할 수 있습니다:

- **경로 지정** (모노레포 지원): `자동사냥 계획 apps/feed` → `apps/feed` 디렉토리만 분석
- **키워드 지정**: `자동사냥 계획 performance` → 성능 관련 개선점에 집중
- **조합 가능**: `자동사냥 계획 apps/feed performance` → 특정 앱의 성능 분석

인자가 없으면 전체 코드베이스를 분석합니다.

## 수행 단계

### 1단계: 대상 범위 결정

1. `$ARGUMENTS` 파싱:
   - 경로가 존재하면 (`apps/`, `packages/`, `src/` 등) → 해당 디렉토리로 범위 제한
   - 키워드만 있으면 → 전체 코드베이스에서 해당 영역 집중 분석

2. 대상 경로 확인:
   ```
   분석 대상: [경로 또는 "전체"]
   집중 영역: [키워드 또는 "전체"]
   ```

### 2단계: 코드베이스 분석

다음 영역들을 탐색하며 개선점을 찾습니다:

#### 코드 품질
- 중복 코드 패턴 탐지
- 복잡도가 높은 컴포넌트 (200줄 이상)
- 하드코딩된 값들
- 타입 안전성 개선 가능 영역
- 에러 처리 미흡 영역

#### 성능
- 불필요한 리렌더링 가능성
- 데이터 페칭 최적화 여지
- 번들 사이즈 개선 가능 영역
- 이미지/에셋 최적화

#### UX 개선
- 로딩 상태 UX
- 에러 상태 UX
- 폼 유효성 검사 피드백
- 모바일 반응형 개선
- 접근성 개선

#### 신규 기능 제안
- 사용자 편의 기능
- 자동화 가능 영역
- 통계/분석 기능
- 통합 기능

### 3단계: 기존 Todo 확인

1. `/todos/` 디렉토리의 모든 `.md` 파일 읽기
   - **Glob 도구**로 `todos/**/*.md` 패턴 검색 (하위 폴더 포함)
   - **Read 도구**로 각 파일 내용 읽기
2. 이미 등록된 개선 항목 목록 파악
3. 중복 제안 방지

### 4단계: 새 아이디어 문서화

발견한 개선점 중 기존 todo에 없는 항목들을 markdown으로 작성합니다.

#### 저장 위치 규칙 (모노레포 지원)

**특정 경로가 지정된 경우:**
- `/todos/[경로]/` 하위에 저장
- 예: `자동사냥 계획 apps/feed` → `/todos/apps/feed/feature-name.md`

**전체 분석인 경우:**
- `/todos/` 루트에 저장
- 예: `/todos/feature-name.md`

#### 파일명 규칙
- 케밥 케이스 사용: `feature-name.md`
- 명확하고 간결하게

#### 문서 형식
```markdown
# 제목

## 상태
<!-- 작업 상태 추적 -->
- [ ] 미시작

## 대상
<!-- 모노레포에서 어느 프로젝트/패키지에 해당하는지 -->
- 경로: `apps/feed` (또는 `전체`)
- 카테고리: refactor / feature / ux / performance / dx / infra

## 개요
간단한 설명 (1-2문장)

## 현재 문제점 (선택)
현재 방식의 문제점이나 개선이 필요한 이유

## 구현 계획

### Phase 1: [단계명]
- 작업 내용 1
- 작업 내용 2

### Phase 2: [단계명]
- 작업 내용 1
- 작업 내용 2

## 영향받는 파일
- `apps/feed/src/path/to/file.tsx`
- `packages/shared/src/another.ts`

## 우선순위
High / Medium / Low

## 예상 작업량
- 👤 사람: [시간/일 단위]
- 🤖 Claude Code: [시간/일 단위]
```

### 5단계: 결과 출력

작업 완료 후 다음 정보를 표시합니다:

1. **요약 메시지**
   ```
   📍 분석 대상: [경로]
   총 N개의 새로운 개선 아이디어가 추가되었습니다.
   ```

2. **추가된 항목 목록**
   | 파일명 | 제목 | 대상 | 우선순위 | 카테고리 |
   |--------|------|------|----------|----------|

3. **각 파일의 전체 내용**
   - 파일명과 함께 markdown 내용 표시

## 카테고리 분류

- **refactor**: 코드 품질 개선
- **feature**: 신규 기능
- **ux**: 사용자 경험 개선
- **performance**: 성능 최적화
- **dx**: 개발자 경험 개선
- **infra**: 인프라/배포 관련
